### 升级版需求识别逻辑解说

- 在新版打表手段基础上升级，增加了建筑配置识别和炮塔弹药类型识别
- 初始化阶段通过 `op add 建筑名 @counter N` + `jump` 跳转的方式为每种建筑设置需求物品
- 使用 `sensor config bd @config` 读取建筑配置，`sensor @name` 获取配置名称，再 `read @counter @this configName` 读取跳转偏移
- 使用 `sensor ammoT bd @currentAmmoType` 识别炮塔当前弹药类型，并写入需求表
- 通过 `op shl mask 1 i` + `op or list list mask` 将需求物品打包为位图
- 最终将物品列表（位图）写入主逻辑的 `itemList` 变量

### 配置代码逻辑解说

- 通过控制卸载器选择最低数量的物品，适用于工厂物资运输与核心物品装填
- 支持远程容器模式（0: 关闭/1: 远程核心/2: 指定坐标），可通过一次性单位获取远程建筑数据
- 支持阈值设置（0-1），可选最少物品或最多物品模式
- 物品清单通过分类器选择/取消，配置代码打包为位图传输
- 配置代码包含物品列表（itemList）、运行状态（running）、控制模式（controlAllBuT）、反向模式（reversed）等信息
- 通过 `op log` + `op idiv` 从位图中提取最低位/最高位的物品索引
- 使用 `control config` 设置卸载器/分类器的目标物品
- 使用 `control enabled` 控制物品源的开关状态
