Mindustry Logic 汇编指令学习总结

概述

本文档是基于 Mindustry 159.7 版本源码（LExecutor、LCategory、LogicOp 等）和教学文档（MlogDocs、learn-mindustry-logic）的学习总结，系统梳理了 Mindustry logic 汇编语言的变量类型系统、指令分类、完整指令列表、运算符、环境变量、单位控制子指令、代码示例与关键实现细节。

Mindustry 的 logic 是一种基于行的类汇编语言，运行在微处理器（Micro Processor）、逻辑处理器（Logic Processor）和超频处理器（Hyper Processor）上，世界处理器（World Processor）则额外支持 world 类指令。每行一条指令，参数以空格分隔，# 开头为注释，支持标签跳转。

本文档中的代码示例严格符合 logic 的导入导出格式，可直接粘贴到处理器中使用。

2. 变量类型系统

Mindustry logic 是一种动态弱类型语言，变量没有显式类型声明，值本身携带类型信息。源码中通过 LVar 类的 isobj 标记区分"对象引用"和"纯数值"。主要类型如下：

2.1 number（数值）

整数和小数统一存储为 double。支持十进制、十六进制和二进制字面量。

123      # 十进制整数
-2       # 负数
1.5      # 小数
0xFF     # 十六进制（255）
0b101    # 二进制（5）

2.2 null（空值）

未赋值变量的默认值，或除以 0 的结果。null 在数值运算中按 0 处理，在布尔判断中为 false。

set x 0
op div result 1 x      # result 为 null

2.3 string（字符串）

用双引号 " 包裹，支持 \n 换行和颜色渲染标记（如 [red]、[green]）。颜色标记会在显示时渲染。

print "[red]警告[/red] \n [green]正常[/green]"

2.4 content（游戏内容）

以 @ 开头的内置变量，代表一种"类型"而非具体实例。例如 @copper 代表铜矿物品类型，@poly 代表 poly 单位类型，@sorter 代表分类器建筑类型。可用于 sensor 查询、ubind 绑定、lookup 返回等。

2.5 building（建筑实例）

特定的建筑对象引用，通过 getlink、sensor、ulocate 等指令获取。可以对其执行 control 操作（如开关、射击、配置）。

2.6 unit（单位实例）

特定的单位对象引用，通过 ubind、uradar 等指令获取。绑定后存入 @unit，可通过 ucontrol 控制其行为。

2.7 team（队伍）

表示游戏中的阵营，如 @sharded（玩家方）、@crux（敌方）。可用于 sensor 查询队伍或作为参数传递。

2.8 enum（枚举）

预定义的枚举常量，如 @ctrlProcessor(1)、@ctrlPlayer(2)、@ctrlCommand(3)，表示单位当前被谁控制。

以下示例严格符合 Mindustry logic 的导入导出格式：每行一条指令，参数用空格分隔，# 开头为注释，支持标签（如 loop:）。可直接粘贴到处理器中使用。

示例 1：Hello World

示例 2：计数器

使用标签和 jump 实现循环，不断递增计数并打印。

mlogset count 0
loop:
op add count count 1
print "count: "
print count
print "\n"
printflush message1
jump loop always 0 0

示例 3：遍历链接建筑

使用 getlink 遍历所有链接建筑，用 sensor 统计物品总数。

mlogset i 0
loop:
getlink b i
sensor amount b @totalItems
op add total total amount
op add i i 1
jump loop lessThan i @links
print "total items: "
print total
printflush message1

示例 4：绑定单位并移动

使用 ubind 绑定 poly 单位，读取其坐标后控制其移动。

mlogubind @poly
sensor ux @unit @x
sensor uy @unit @y
ucontrol move ux uy 0 0 0

示例 5：雷达搜索并攻击

绑定 flare 单位，用 uradar 搜索最近的敌人并攻击。

mlogubind @flare
uradar enemy any any distance 0 1 target
ucontrol targetp target 1 0 0 0

9. 关键实现细节

以下细节源自 Mindustry 源码分析，有助于理解 logic 的底层运行机制。

9.1 坐标系统

logic 中的坐标是世界坐标（像素），而非方块坐标。源码中通过 World.unconv() 将方块坐标转换为像素坐标用于逻辑运算。例如 @thisx、@thisy 返回的是处理器建筑中心的像素坐标，建筑尺寸为 8 像素/格。

9.2 变量存储

LVar 类是 logic 中所有变量的基础结构，内部有 isobj 布尔标记：为 true 时，变量存储对象引用（building/unit/content/string）；为 false 时，变量存储 double 数值。运算时会自动判断是否为对象以决定比较方式（strictEqual 即基于此区分）。

9.3 链接验证

control 指令在执行时会验证目标建筑在处理器链接范围内。若目标建筑未链接到当前处理器，指令将被忽略。getlink 获取的建筑一定是有效的链接对象。世界处理器的 fetch 指令则通过全局索引获取建筑，不受链接范围限制。

9.4 雷达缓存

radar 与 uradar 的搜索结果会缓存约 30 tick。这意味着在同一缓存周期内多次调用 radar 返回相同结果，且能显著降低性能开销。设计高频雷达逻辑时需注意此缓存机制可能导致的延迟。

9.5 特权限制

非特权处理器无法使用 world 类指令。getblock、setblock、spawn、spawnwave 等指令仅世界处理器（World Processor）可用。普通处理器调用 world 指令不会产生效果。世界处理器是专门用于操控全局游戏状态的特殊处理器。

9.6 单位控制超时

单位被 ucontrol 控制后，若 10 秒内未收到新的控制指令，将自动恢复原始 AI 行为。这是防止处理器失联后单位永久卡死的保护机制。因此需要持续控制的单位应在主循环中定期（如每秒）发送控制指令。

9.7 物品传输延迟

ucontrol itemDrop / itemTake 指令存在 1.5 秒的冷却延迟。在此期间单位无法再次执行物品传输操作。设计自动化物流时需将此延迟纳入考虑，避免因过快调用导致指令被忽略。

本文档基于 Mindustry 159.7 版本。不同版本间指令参数、运算符列表及行为可能存在差异，使用时请以游戏内处理器编辑器的实时提示与实际版本源码为准。
